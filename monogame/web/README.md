# monogame/web/: the browser runtime

The browser build of the client (`Client/PristonTale.Web`) runs the same game, renderer and fork of MonoGame as the desktop
client. What changes is what lies under the framework: this folder replaces the native runtime (`mgruntime`: Vulkan, SDL2,
FAudio) with managed code and a WebGPU replayer in JavaScript.

## How it fits together

| Part | Where | What |
|---|---|---|
| Interop declarations | `generate_interop.py` -> `Interop.g/` | Every `[DllImport]` of `framework/.../Platform/Native/*.Interop*.cs` becomes a partial method, so the compiler reports a runtime function the web lacks or a declaration that changed. Generated by the build, not committed. |
| Graphics | `Graphics.Web.cs`, `WebStream.cs` | The `MGG_*` calls, written to a command stream in shared memory. |
| Replay | `Client/PristonTale.Web/wwwroot/mgweb.js` | Reads the stream on the page's thread and issues WebGPU calls. |
| Platform | `Platform.Web.cs`, `Assets.Web.cs` | The canvas as the window, input events from a shared queue, content through the file tree. |
| Game files | `wwwroot/mgfiles.js`, `make_files_manifest.py` | The game data as a file tree: every file exists with its size and downloads on first read. |
| Effects | `convert_effects.py` | The SPIR-V inside each compiled effect becomes WGSL; everything else in the effect stays. |
| Network | `Shared/PristonTale.Protocol/Transport/WebSocketTransport.cs` | The same frames over a WebSocket to the site's bridge, which holds the TLS connection to the server. |

The framework project builds this in place of the native declarations when `EtervaleWeb=true`
(`MonoGame.Framework.Native.csproj`). The operation numbers in `WebStream.Op` and the enum values in `mgweb.js` must match.

## Threads

.NET's main thread (the "deputy", a worker) is the only one that can call JavaScript and it is where browser networking
completes, so it must stay free. The game's blocking loop runs on a thread of its own (`Client/PristonTale.Web/Program.cs`).
The page's thread cannot call C# synchronously, and a synchronous call from C# to JavaScript costs tens of microseconds; that
is why graphics is a stream and not calls. The game thread writes the stream and waits only at `Present`, to pace itself by
the display, and for read-backs.

## What differs from the Vulkan runtime

- A texture size of zero in `Texture_SetData` and `Texture_GetData` means the whole mip level, as in the native runtime.
- Samplers bind at 128 + slot, since WebGPU cannot share a binding number between a texture and a sampler (textures 32 +
  slot, writable resources 64 + slot, constants at the slot; vertex stage group 0, pixel stage group 1, compute group 0).
- Constant buffers are copied into one arena per submit and bound with dynamic offsets.
- Bind group layouts are chosen from what is bound, since a depth surface or unfilterable format needs its own layout.
- `Depth32Float` render targets are the pass's depth attachment with no colour, as in the native runtime.
- Multisampling resolves when a pass ends, and uses 4 samples for any requested count above 1.
- The back buffer is an offscreen texture copied to the canvas at `Present`, so a frame may span several browser tasks.

## Not implemented yet

- Audio has no reverb, and a looped sound of 20 s or more counts as music for the volume sliders: the game has no sound
  categories of its own. `Audio.Web.cs` writes to a locked queue, since sounds start on several threads, and `mgaudio.js` plays
  it; a voice's state comes from its clock on the C# side. Browsers stay silent until the player first clicks or presses a key.
- Media and storage: `Media.Interop.cs` and `Storage.Interop.cs` are generated as empty stand-ins.
- Timestamps, frame capture and pipeline statistics report as unavailable. Occlusion queries always report visible.
- `Bgr565`, `Bgra5551`, `Bgra4444`: mapped to `rgba8unorm` with the wrong row size; no game asset is known to use them.
- `wwwroot/preload.json` lists the files the start reads (downloaded first, with progress, in parallel) and those the first
  world reads (downloaded in the background into the browser's HTTP cache). It was recorded from a run and must be recorded
  again when the data changes. Any other file downloads with a synchronous request on the page's thread when first read, which
  stalls the page for that download; other fields rely on this.
- The game's custom cursors are not shown: the page keeps the browser's cursor.
- The built-in `SkinnedEffect` does not convert (`convert_effects.py` reports it); the game uses its own effects.

## The site's panels

`Client/PristonTale.Web/Program.cs` exports what the page may ask of the game, queued for the game thread by `WebGame`.
Reflection-based JSON serialization on .NET's main thread never returned, so `ReadConsole` answers in plain text.

- Settings (`wwwroot/settings.js`): the game's `ClientSettings` file, restored from `localStorage` before the game starts and
  saved back as it changes; changes reach the game through `ApplySettings`. Its own options (volumes, resolution) are the site's.
- Admin (`wwwroot/admin.js`): sends chat lines through `GameConsole`, the same lines a game master can type. The server checks
  the level of each and writes `gm_audit`, so the panel grants nothing and is shown only to accounts that have a level. Set one
  with `DevAccounts set-gm <account> <level>`.

## Build

```powershell
powershell -ExecutionPolicy Bypass -File Client/PristonTale.Web/build_web.ps1 -Output <folder> -Work <folder> -Naga <naga.exe>
```

It needs the .NET 10 SDK with the `wasm-tools` and `wasm-experimental` workloads, the .NET 8 runtime (the content builder),
`naga` (`cargo install naga-cli`), Python and `dotnet tool restore`. The page must be served with the headers in the site's
`web.config` (`Cross-Origin-Opener-Policy`, `Cross-Origin-Embedder-Policy`), over HTTPS except on localhost. The site also
serves the game data at `assets/` and bridges `ws?port=10009` to the game server.

The browser build has been run on Windows only, in Edge's Chromium engine with an NVIDIA GPU.
